# Pet Rock — Telegram-бот воронки и админка

Бот ведёт человека по VSL-воронке «Операция Pet Rock»: выдаёт видео, 24 часа дожимает сообщениями,
кружками и картинками до оплаты «Метода AFK» и закрывает доступ. Вся воронка — тексты, медиа, кнопки,
паузы и порядок — хранится в базе и правится в админке, без кода.

## Из чего состоит

| Папка | Что это |
|---|---|
| `api/` | API с данными (Express + PostgreSQL). Единственный, кто ходит в базу. Закрыт токеном |
| `bot/` | Бот (grammY, long polling) и его HTTP-сервер: трекинг ссылок, страница с видео, хук оплаты |
| `admin/` | Админка: сервер (Express) и интерфейс без сборки (`public/`) |
| `db/schema.sql` | Схема базы, применяется миграцией при каждом запуске API |
| `test/e2e.mjs` | Сквозные тесты: настоящие API, SQL и админка, поддельный Telegram |

```
Telegram ⇄ bot ──HTTP + токен──▶ api ──▶ PostgreSQL
                 admin ──────────▶ api
```

Бот держит воронку в памяти и перечитывает её раз в 10 секунд: правка в админке доходит почти сразу,
а падение API не останавливает отправку.

## Как работает воронка

- Отсчёт от первого /start (Т0). Доступ к видео — 24 часа (настройка `access_hours`).
- Т0: «Доступ открыт» с кнопкой канала, через 5 секунд — ссылка на видео.
- Три ветки идут параллельно, в каждой точке человек получает сообщение только своей:
  «не нажал на видео», «нажал, но не досмотрел», «досмотрел до оффера, но не купил».
- Время точки считается от события-якоря (Т0, момент оффера), а не от предыдущего сообщения —
  задержки не копятся. После дедлайна уходит только «Доступ закрыт», без пачки пропущенных.
- После оплаты дожимы отменяются и уходит одно сообщение «Оплата прошла».
- Тестовый режим `/test` для админов: часовые паузы сжаты в 100 раз.

Подстановки в текстах: `{deadline}` — «1 октября, 14:05 МСК», `{price}`, `{email}` — почта
человека с лендинга, `@{support}` — поддержка из настроек. Ссылки внутри текста:
`<a href="{video_link}">…</a>` (а также `channel_link`, `offer_link`, `support_link`, `youtube_link`).

## Админка

| Раздел | Что делает |
|---|---|
| Схема | Холст воронки: блоки, стрелки, паузы, тексты, медиа, кнопки |
| Рассылки | Конструктор сообщения, сегменты, тест себе, запуск и остановка |
| Люди | Цифры воронки, поиск, карточка с историей и очередью |
| Заявки | Заявки с лендинга: метки и докуда дошёл человек; воронка по utm-меткам |
| Настройки, Аккаунты | Ссылки, цена, ключи, роли: владелец, редактор, маркетолог, наблюдатель |

Видео при загрузке: размеры и длительность сервер читает из файла, обложку делает браузер —
Telegram показывает видео в нужных пропорциях и с превью.

## Интеграции

**Лендинг.** Лендинг шлёт заявку на `POST /hooks/lead` админки с заголовком `X-Api-Key`
(ключ — в Настройках) и ведёт человека в бота по ссылке `https://t.me/<бот>?start=<lead_id>`.
Тело — JSON: `lead_id` (обязательно; латиница, цифры, `-`, `_`, до 64 символов), `email`, `name`,
`phone`, `utm_source` … `utm_term`, любые другие поля. Порядок заявки и /start не важен, повтор с тем же
`lead_id` не создаёт дубль.

**Google Таблица.** `GET /hooks/leads.csv?key=<ключ выгрузки>` — CSV со всеми заявками и этапами.
В таблицу: `=IMPORTDATA("https://<админка>/hooks/leads.csv?key=…")`.

**GetCourse.** Хук оплаты бота: `/hooks/gc/payment?secret=<HOOK_SECRET>&email=…&user_id=…`
(GET или POST). Человек находится по почте или по id пользователя GetCourse из ссылки `start=u<ID>`.

**Видео.** Страница `/w/<токен>` бота с плеером Vturb (код плеера — в Настройках) засчитывает
«досмотрел до оффера» на заданной секунде.

## Запуск в Docker

```bash
cp .env.example .env        # заполнить токен бота, секреты, PUBLIC_URL
docker compose up -d --build
```

Наружу на `127.0.0.1` открыты бот (`:3025`) и админка (`:3026`). Перед ними нужен прокси с HTTPS:
адрес бота — тот, что в `PUBLIC_URL`, админка — на своём домене. Если прокси в Docker-сети или на
хосте не через loopback — это уже учтено (`TRUST_PROXY: loopback, uniquelocal`).

## Запуск без Docker

Node.js 22 и PostgreSQL. В каждой из папок `api/`, `bot/`, `admin/`: `npm ci`, `.env` по образцу
`.env.example`. Затем `npm run migrate` в `api/` и `node src/server.js` / `node src/index.js`.

## Тесты

```bash
TEST_DATABASE_URL=postgres://user:pass@host:5432/test_db node test/e2e.mjs
```

Нужна отдельная пустая база: тест очищает её до и после прогона.

## Переезд с работающего сервера

1. **Один токен — один бот.** Пока работает старый бот, новый с тем же токеном запускать нельзя:
   Telegram отдаёт сообщения только одному из них.
2. **Данные — дампом базы** (`pg_dump`): там воронка, медиа, люди, очередь сообщений, заявки и аккаунты
   админки. Пустая база получит только стартовую воронку без медиа.
3. **Старые ссылки.** В уже отправленных сообщениях ссылки ведут на старый `PUBLIC_URL`
   (`/c/…`, `/w/…`) — со старого адреса нужен редирект на новый.
4. **Внешние адреса:** приём заявок у лендинга, хук оплаты в GetCourse, формула в Google Таблице.
